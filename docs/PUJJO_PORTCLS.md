# Pujjo PortCls and analog routes

The PCI function remains a KMDF resource and DMA owner. The guarded DMIC path publishes a static child PDO after firmware boot, an exact ACPI NHLT format match, and module resource validation. A separate WDM driver binds to the child ID and uses the documented PortCls adapter and subdevice APIs. The microphone topology and WaveRT capture filters connect on the PortCls FDO. [Microsoft SysVAD adapter](https://github.com/microsoft/Windows-driver-samples/blob/main/audio/sysvad/adapter.cpp) · [SysVAD subdevice registration](https://github.com/microsoft/Windows-driver-samples/blob/main/audio/sysvad/common.cpp)

The versioned query interface holds a parent reference for every WaveRT miniport and stream that uses it. The parent serializes allocation, transitions, disconnect, and release. The stream withdraws its buffer from position and notification callbacks before releasing the MDL and DMA references. Parent D0 exit revokes hardware access and drains notifications before releasing MMIO. A descriptor with an unconfirmed stop remains quarantined with its buffers until device removal. Device restart with retained streams and automatic DSP resume remain closed.

The default build gates audio and DSP activation. The guarded microphone path requires the reviewed firmware build, audio build flag, existing canary and explicit settings. It supports an exact stereo 48 kHz NHLT format. RT5682S framing and RT1019P logical GPIO polarity can be checked offline. Headset and speaker routing still require board-specific endpoint evidence. [RT5682S register and clock fields](https://github.com/torvalds/linux/blob/v6.13/sound/soc/codecs/rt5682s.h) · [RTL1019 amplifier reference](https://github.com/torvalds/linux/blob/v6.13/sound/soc/codecs/rt1015p.c)

The [resource diagnostic package](PUJJO_DIAGNOSTIC_PACKAGE.md) is staged independently of the PortCls child and DSP packages.


## Analog route ownership

The guarded analog path supports separate PortCls headphone, headset microphone, and speaker children. An approved kernel board profile and exact SSP NHLT configuration are required to publish each child. The driver currently supplies no such profile. The headphone and headset microphone use SSP0 and share the RT5682S. The speaker uses SSP1 and the RTL1019 amplifier. Only one analog stream can own the peripheral and its SSP route at a time. That restriction keeps concurrent codec register writes and conflicting codec clocks out of the initial implementation. The DMIC path has separate ownership.

A stream starts the DSP route muted, applies the qualified playback gain limit, and establishes the SSP clocks. The codec then verifies identity and configures its AIF1 and digital DAC or ADC route. It then executes the approved analog power, bias and routing steps with bounded settling delays and readback. Teardown unwinds changed fields with the supplied restore delays. Headphone playback checks JD1 presence. Headset capture requires a fresh combo-jack classification. The amp instead drives the qualified shutdown polarity and waits for calibration with DSP mute held. Stop requests DSP mute, shuts down the amplifier or restores codec register fields while clocks are present, and stops DMA. Parent D0 exit revokes active leases. A failed stop is surfaced and blocks further use.

Before authorizing a board profile, verify clock source, frequency, polarity and slot framing against the actual Windows NHLT and SSP signals. Establish the RT5682S analog rail, headphone and headset microphone pin, mic bias, gain and JD1 initialization required by this board. Establish RT1019P shutdown polarity, calibration time, and the safe calibrated speaker gain range using Pujjo-specific evidence. Validate jack interrupts and Windows hotplug reporting separately. The current implementation checks physical state when opening a route. Automatic DSP resume still requires cAVS power, DMA and IPC requalification.
